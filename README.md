# WLED для intraHouse / IntraSCADA v5

Плагин подключает ESP32-контроллеры DOMRAEM и другие контроллеры с прошивкой WLED к intraHouse. Он работает по локальному JSON API, без MQTT и дополнительных npm-пакетов. Для каждого контроллера настраивается отдельный экземпляр плагина.

## Что понадобится

- Работающий контроллер WLED, подключённый к сети.
- Сервер intraHouse / IntraSCADA v5 с доступом к HTTP API контроллера. Если intraHouse запущен в контейнере, проверьте доступ из сети этого контейнера.
- Стабильный адрес контроллера. Подойдёт IP с DHCP-резервацией или DNS-имя, которое разрешается на сервере intraHouse.

Проверьте связь с сервера intraHouse. Подставьте адрес своего контроллера.

```sh
curl -fsS http://192.0.2.10/json/state
```

В ответе должен прийти JSON с полями `on`, `bri` и `seg`. Адрес `192.0.2.10` здесь и далее используется только как пример.

## Установка плагина

1. [Скачайте установочный архив intrahouse-wled-1.0.0.zip](https://github.com/apnagaev/intrahouse-wled-plugin/raw/refs/heads/main/downloads/intrahouse-wled-1.0.0.zip).
2. В панели сервера intraHouse откройте **Плагины → Import**, выберите скачанный ZIP, затем обновите страницу **Project Manager**.
3. В дереве плагинов проекта откройте контекстное меню **WLED** и добавьте экземпляр. Например, создайте по одному экземпляру для контроллеров спальни и кухни.
4. Заполните параметры экземпляра, сохраните настройки и запустите его. В списке каналов проверьте, что `online` имеет значение `1`.
5. Если вместо импорта требуется ручная установка, распакуйте папку `wled` из архива в каталог `plugins` рабочей директории сервера. После распаковки путь к манифесту должен оканчиваться на `plugins/wled/manifest.json`. Затем обновите Project Manager и добавьте экземпляр по шагам выше.

Для импорта используйте архив из раздела выше. Он содержит папку `wled/` в корне.

## Параметры экземпляра

| Параметр | По умолчанию | Что указывать |
| --- | --- | --- |
| IP или имя WLED (`host`) | Пусто, обязательный | IP, имя или адрес с портом. Например, `192.0.2.10`, `wled-bedroom.local` или `192.0.2.10:8080`. Допускаются `http://` и `https://`. Путь `/json/state` плагин добавляет сам. |
| Опрос (`pollSeconds`) | 5 секунд | Целое число от 1 до 300. В этом интервале плагин запрашивает состояние, чтобы увидеть и внешние изменения. |
| Тайм-аут (`timeout`) | 2500 мс | Целое число от 250 до 15000. Предельное время одного HTTP-запроса. |
| ID сегмента (`segment`) | −1 | `-1` выбирает главный сегмент WLED. Для конкретного сегмента укажите его числовой ID от 0 до 255. |

Для первой проверки достаточно указать адрес. После изменения параметров перезапустите экземпляр. При HTTPS сертификат должен быть доверенным для среды Node.js, в которой работает intraHouse.

## Привязка к устройству intraHouse

1. Создайте устройство подходящего типа или откройте существующий светильник.
2. Во вкладке **Каналы** экземпляра привяжите `on` к свойству состояния светильника. Включите чтение и запись, чтобы intraHouse мог управлять светом и получать изменения из WLED.
3. Если нужна регулировка яркости, привяжите `brightness` к числовому свойству со шкалой 0–100. Для `color` используйте строковое свойство. Для пресета, эффекта и палитры используйте числовые свойства.
4. Проверьте управление в обе стороны. Включите свет из intraHouse, затем выключите через веб-интерфейс WLED. Состояние в intraHouse обновится при очередном опросе.

| Канал | Доступ | Значение |
| --- | --- | --- |
| `online` | Чтение | `1` при успешном обмене, `0` при ошибке связи. |
| `on` | Чтение и запись | `0` или `1`. Общее питание лент контроллера. |
| `brightness` | Чтение и запись | Общая яркость 0–100%. Запись нуля выключает свет. Запись ненулевого значения включает свет с указанной яркостью. |
| `preset` | Чтение и запись | Запишите ID существующего пресета от 1 до 250. WLED может вернуть `-1`, если активного пресета нет. |
| `color` | Чтение и запись | Основной цвет выбранного сегмента в формате `#RRGGBB` или `#RRGGBBWW`. Например, `#FF6000` или `#FF600020`. |
| `effect` | Чтение и запись | Числовой ID эффекта выбранного сегмента. Список доступен в `/json/eff`, нумерация с нуля. |
| `palette` | Чтение и запись | Числовой ID палитры выбранного сегмента. Список доступен в `/json/pal`, нумерация с нуля. |
| `segment_available` | Чтение | `1`, если контроллер отвечает и выбранный сегмент существует. |

Цвет, эффекты и палитры применяются к выбранному сегменту. Питание, яркость и пресеты управляют контроллером целиком. Если в WLED настроена UDP-синхронизация, команды могут затрагивать другие контроллеры согласно настройкам группы WLED.

## Если что-то не работает

- **WLED не появился в дереве.** Проверьте, что импортировали установочный ZIP и обновили Project Manager. При ручной установке проверьте расположение `manifest.json`.
- **`online = 0`.** Проверьте `/json/state` с хоста intraHouse, адрес, порт и журнал экземпляра. Если `.local` не разрешается из контейнера, используйте IP.
- **Питание работает, цвет или эффект не меняется.** Проверьте `segment_available` и ID сегмента. Допустимые ID эффектов и палитр смотрите на самом контроллере.
- **Связь пропала, а на экране осталось старое состояние.** При ошибке плагин выставляет `online = 0` и `segment_available = 0`. Остальные каналы хранят последнее полученное значение до восстановления связи.
